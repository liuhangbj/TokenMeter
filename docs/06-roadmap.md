# TokenMeter 开发路线图

> 更新日期：2026-08-12

## 产品边界

TokenMeter 的核心定位是：**在一个简洁的托盘面板中，一眼看清所有 AI 账户的套餐余量、API 余额、重置时间和健康状态。**

后续开发继续遵循以下原则：

- 优先保证数据准确、刷新可靠和跨平台一致，再扩大供应商数量。
- 新供应商必须提供有意义的余额、额度或用量数据，不为了平台数量增加空壳入口。
- 继续使用标准账户契约和通用卡片，不为单个供应商另造 UI 模板。
- 保持“零数据库”设计，不在本地保存长期用量历史，也不发展成复杂账单分析工具。
- 非公开接口必须明确稳定性和降级路径，无法可靠获取的数据不伪造、不推算。

## 近期：0.9.7 稳定性、三家接入与视觉升级

0.9.7 采用三条并行工作线：稳定性仍是发布门槛，同时推进视觉识别升级和火山引擎方舟接入。新功能完成不应挤占跨平台回归和数据准确性修复。

### A. 稳定性工作线

- ✅ 自动更新采用“后台定时检查并下载、用户点击升级并重启”的确认式流程；不静默安装、不擅自退出，网络失败会延迟重试，重启前下载状态可恢复。

1. **Windows 完整回归**
   - ✅ 2026-08-10 已完成基础冒烟测试，接入一至两个供应商并正常使用，未发现明显异常。
   - 验证 Codex、Claude、OpenRouter 的浏览器授权和本机凭证导入。
   - 验证托盘点击、窗口定位、任务栏隐藏、失焦关闭和重复点击行为。
   - 验证自动更新、开机启动、安装与卸载。
   - 当前结论仅代表基础链路可用；全供应商、全部认证方式和更新链路仍需后续矩阵验收。

2. **macOS Intel 验收**
   - ✅ 2026-08-10 已在真实 Intel Mac 上完成 `0.9.6` 启动与使用验收，未发现异常。
   - CI 继续使用原生 Intel runner 检查 `x86_64` 架构，禁止误发 ARM 或 Universal 产物。

3. **套餐账号实测**
   - Claude Plan。
   - GLM Coding Plan。
   - MiniMax Token Plan。
   - 为每种真实返回结构保存脱敏测试样本，补齐映射回归测试。

4. **GLM API 余额语义**
   - 主值使用服务端明确返回的可用余额。
   - 现金、信用额度、赠送金额只作为余额分项，不重复累加。
   - Token 和请求次数资源包保持独立额度项，并显示各自单位、余量和有效期。
   - 未知字段不参与总额计算，先通过脱敏样本确认语义。

5. **真正的一键自动更新**
   - 应用启动后自动检查更新，并在后台按合理间隔再次检查，不依赖用户进入设置页。
   - 检测到新版本后自动下载更新包；签名验证成功后再弹出更新提示。
   - 提示中展示新版本号、更新摘要和安装操作，用户点击一次即可安装并重启应用。
   - 下载、验签、安装或重启失败时必须显示可理解的错误，并保留“稍后重试”和手动检查入口。
   - 从已安装旧版本实际升级到新版本，完成一次端到端自动更新测试，不能只验证 `latest.json` 和下载链接。
   - ARM Mac、Intel Mac、Windows 三个平台都必须进入同一份 `latest.json`。
   - 清理 GitHub Actions 的 Node 运行时弃用警告。

6. **脱敏诊断导出**
   - 导出供应商类型、认证方式、HTTP 状态、字段路径、字段类型和解析结果。
   - 自动删除 API Key、Token、Cookie、邮箱、账号 ID 等敏感信息。
   - 支持用户在无法提供真实账号时提交可复现的接口结构样本。

### B. 视觉识别工作线

- ✅ 2026-08-12 完成“六边形信号孔径”应用图标、macOS 模板菜单栏图标和 Windows 彩色托盘图标。
- ✅ 2026-08-12 建立“风格 × 明暗外观”主题契约；完成 Classic、Claude 和 Cyber 三套风格的浅色、深色与系统跟随，覆盖主面板、设置、添加向导和认证表单。
- 图标保持简洁、科技感和小尺寸识别度，避免依赖细碎装饰或复杂文字。
- 分别检查 macOS Dock、Windows 应用列表、安装包、设置页和高分辨率显示效果。
- 同步探索菜单栏图标的轮廓方向，保证应用图标与菜单栏图标属于同一视觉体系，但不强求使用同一个复杂图形。
- 先制作多组方向稿，再确定最终图形、色彩和明暗背景适配，不直接用第一版概念稿替换正式资源。

### C. 火山引擎方舟工作线

火山引擎方舟调整为下一家优先接入的供应商，首期以官方 API 能稳定返回的账户数据为边界。

- ✅ 已接入费用中心官方 `QueryBalanceAcct`：可用余额、现金余额、信用额度、冻结金额和欠费金额。
- ✅ 已实现火山 OpenAPI HMAC-SHA256 签名和 AK/SK 添加入口。
- ⏳ 待真实火山账户对签名、权限和字段样本做验收；方舟资源包/Token 用量后续在官方字段稳定后补充。

### D. Gemini 与 SiliconFlow

- ✅ Gemini 对齐 Google 官方 Gemini CLI：Google OAuth、本机 CLI 凭证导入、套餐档位、模型配额桶、重置时间和 AI Credits。
- ✅ SiliconFlow 支持国内/国际站 API Key，总余额、充值余额和赠送余额映射到统一卡片。
- ⏳ 两家均待真实账户保存脱敏响应样本并完成跨平台验收。

接入步骤：

1. 调研官方认证方式、余额接口、账单接口、Token 用量接口、资源包和赠送额度字段。
2. 判断方舟账户应拆分为按量 API、资源包或其他独立产品类型，避免把不同计费语义混在一个账户中。
3. 确认账户身份字段、货币单位、时区、账期、分页和多币种规则。
4. 建立套餐映射和字段映射，接入现有标准账户契约。
5. 支持同一厂商添加多个账户，不限制 API Key 数量。
6. 使用脱敏真实响应建立 fixtures，覆盖正常、零余额、多资源包、赠送金额、鉴权失败和限流状态。
7. 使用通用供应商卡片和添加向导，不增加方舟专属 UI 模板。

火山方舟首期完成标准：

- 可以稳定添加、删除、刷新多个账户。
- 主值没有重复计算，余额和额度项的单位正确。
- API 返回的可用分项尽量完整映射，未知字段安全忽略。
- 错误状态可见，不把鉴权失败显示为零余额。
- macOS ARM、macOS Intel、Windows 三个平台行为一致。

## 中期：0.10 供应商平台化

现有标准账户契约不再进行大规模重构，下一阶段把它固化为可长期扩展的 v1 规范。

### 契约与测试

- 固定账户类型：套餐、按量、Token Plan。
- 固定主值、进度项、余额项、套餐徽章、身份字段和重置时间的语义。
- 每个供应商维护脱敏响应样本和契约测试。
- 所有供应商统一覆盖多账户、刷新、删除、别名和错误状态。
- 增加供应商接入模板，使新平台主要工作收敛为认证、字段映射和套餐映射。

### 后续供应商顺序

1. 小米 MiMo。
2. 阿里云百炼 / Qwen。

每个平台在实现前先确认是否存在可查询的余额、套餐余量或用量接口。若只能校验 API Key 而无法提供 TokenMeter 的核心信息，则暂缓正式接入。

腾讯 Coding Plan 和腾讯个人 Token Plan 继续等待稳定查询接口，不投入大量精力维护高风险逆向方案。

### 菜单栏主账户与账户汇总栏

1. **主账户定义**
   - 用户可以指定一个全局主账户；未指定时保持现有菜单栏图标，不擅自选择余额最高或最低的账户。
   - 主账户直接复用该账户卡片的主键值，不额外创造另一套健康度计算。
   - 套餐显示剩余百分比，按量账户显示紧凑余额，Token Plan 显示紧凑 Token 余量。

2. **菜单栏图标精修**
   - 精修当前模板图标的轮廓、视觉重心和小尺寸清晰度，并与新应用图标保持同一视觉语言。
   - 评估在菜单栏图标旁显示主账户可用度，例如 `87%`、`$18` 或 `6.2M`。
   - 数字只在主账户数据有效时显示；刷新、离线和鉴权失败不能造成图标闪烁或显示误导性的 `0`。
   - macOS 优先使用原生菜单栏文字能力；Windows 需要单独评估动态托盘图标、提示文字和空间限制，不强求完全相同的呈现方式。

3. **账户主值汇总栏**
   - 在固定标题栏下方增加可收起的紧凑汇总栏，逐个显示各账户名称和主键值。
   - 不把百分比、人民币、美元和 Token 强行相加成没有意义的“总额度”。
   - 点击汇总项可定位到对应账户卡片；账户较多时采用横向滚动、换行或折叠，不挤压卡片主体。
   - 汇总栏与卡片必须使用同一份标准展示数据，刷新后同步更新，不维护第二套字段映射。

以上两项先制作交互原型，确认信息密度和菜单栏占用后再进入正式实现。

- 应用升级时完成配置和凭证的兼容迁移。
- 提供可控的本地日志、脱敏诊断和故障排查入口。

## 1.x：移动端适配

移动端作为独立产品外壳复用现有供应商核心层，不把桌面托盘窗口简单缩小成手机版。

### 前置准备

- 保持供应商认证、刷新、标准账户契约和展示数据与桌面 UI 解耦。
- 提前让通用卡片、汇总栏和设置组件支持窄屏、触控和安全区域。
- 评估 Tauri Mobile 对现有 Rust 依赖、OAuth 回调、系统安全存储和网络请求的支持情况。
- 在实施前决定 iOS、Android 的先后顺序和最低系统版本。

### 移动端形态

- 使用全屏账户仪表盘，不复制菜单栏和托盘交互。
- 支持加密备份导入，安全迁移桌面端保存的账户和凭证。
- 凭证使用 iOS Keychain / Android Keystore 等平台安全存储。
- OAuth 使用系统浏览器和移动端回调，不使用桌面本地端口回调方案。
- 根据系统允许的后台刷新频率更新账户，不能承诺与桌面常驻进程相同的刷新间隔。
- 后续评估桌面小组件、移动端 Widget、低额度通知和生物识别解锁。

### 首期完成标准

- 可以添加、导入、删除和刷新多个账户。
- 主值、分项、套餐映射与桌面端保持一致。
- 前后台切换、网络中断、Token 过期和系统回收后可以安全恢复。
- 凭证不写入明文文件或普通偏好设置。
- 完成至少一个移动平台的真机验收后，再承诺双平台发布时间。

## 稳定后可增加的功能

- 低额度、低余额系统通知。
- 授权即将过期或刷新失败提醒。
- 标题区域显示需要关注的账户数量，但不增加复杂统计组件。
- 单账户刷新与全部刷新分开。
- 账户与设置的加密完整备份和迁移：
  - 必须包含 TokenMeter 已保存的 API Key、OAuth Token 等凭证，否则不提供意义有限的“仅配置导出”。
  - 同时包含账户类型、供应商、昵称、排序、刷新设置和数据结构版本。
  - 备份文件使用用户设置的独立密码加密，不能直接复用仅在当前机器有效的本地主密钥。
  - 导入前预览账户清单，并让用户选择合并或替换；发生账号主键冲突时不静默覆盖。
  - 不提供明文凭证导出模式，不自动上传云端。
- Stable / Beta 更新通道。

## 暂缓事项

- 本地长期用量数据库和复杂趋势图。
- 重型账单分析、成本归因和财务报表。
- 为获取非公开字段而普遍嵌入网页登录。
- 没有余额、额度或用量查询能力的平台占位入口。
- 为单一供应商创建无法复用的卡片或进度条设计。
