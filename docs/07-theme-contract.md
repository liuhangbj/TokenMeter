# TokenMeter 主题契约

主题不是单一配色表，而是由“风格（Theme Family）”和“外观模式（Appearance）”
共同生成的一套完整组件系统。新增主题不得修改账户数据契约或供应商卡片结构。

## 一、持久化模型

- `theme_family`：`classic` / `parchment` / `cyberpunk`
- `appearance`：`system` / `light` / `dark`
- 实际渲染状态写入根节点：`data-theme` 与 `data-appearance`
- `system` 由 `prefers-color-scheme` 解析，系统变化时实时更新，不覆盖用户选择。
- 旧版本只有 `theme` 字段时自动兼容：保留原风格，外观默认 `system`。

## 二、每套风格的必备槽位

### 1. 环境与材质

- `background`：背景底色、壁纸或纹理、环境光、边缘暗角。
- `panel`：主面板材质、边框、圆角或切角、内外阴影。
- `card`：账户卡片材质、层级、品牌高光与悬停形态。
- `overlay`：设置区、添加供应商页、输入框和弹层材质。

### 2. 色彩语义

- `accent-primary`：主操作、高亮状态和焦点。
- `accent-secondary`：只用于少量装饰、次级焦点，不得抢占健康色。
- `text-primary / secondary / muted`：三级文字；每种外观独立校准对比度。
- `border / separator / focus-ring`：结构线、分割线和键盘焦点。

### 3. 套餐色阶

套餐档位始终按月价映射为六档，换主题不得改变档位语义：

| 档位 | 固定色相语义 |
|---|---|
| Free | 中性灰 |
| Tier 1 | 绿色 |
| Tier 2 | 蓝色 |
| Tier 3 | 紫色 |
| Tier 4 | 橙色 |
| Tier 5 | 玫红 / 红紫 |

每档必须提供文字、底色、描边和可选辉光四个变量。辉光只能作为主题表现，
不能代替文字和底色的可读性。

### 4. Token 健康色阶

用量颜色与套餐颜色是两套独立语义，不允许复用套餐档位变量：

| 已用比例 | 状态 |
|---|---|
| `< 50%` | 健康绿 |
| `50–80%` | 深绿 / 青绿 |
| `80–90%` | 琥珀警告 |
| `90–100%` | 红色紧张 |
| `>= 100%` | 深红耗尽 |
| 未知 / 过期 | 中性灰 |

每档必须同时定义状态点、进度条起止色和可选辉光；主账户健康状态只读取主值，
不得被 Credit、Extra Usage 等余额项改变。

### 5. 字体系统

- `font-display`：应用标题、平台名称和关键短标签。
- `font-body`：正文与中文；必须保证小字号可读性。
- `font-data`：余额、百分比、Token、时间和账号 ID，必须使用表格数字。
- 字体必须随应用离线打包，并保留许可证；不得依赖在线字体服务。
- 赛博主题嵌入的 Oxanium 与 Share Tech Mono 均采用 SIL Open Font License 1.1；
  版权与许可证随安装包放在 `THIRD-PARTY-LICENSES.txt`。
- Claude 主题嵌入的 Literata 采用 SIL Open Font License 1.1。

### 6. 控件与图标

- 统一定义按钮、图标按钮、输入框、选择器、进度条、套餐徽章和状态点。
- 每套风格必须规定线宽、端点、圆角或切角、悬停、按下、禁用和键盘焦点。
- 图标仍复用同一 SVG 语义，不为装饰改变图标含义；允许主题通过 CSS 改变描边、
  辉光与容器形态。

### 7. 动效与无障碍

- 所有动效必须响应 `prefers-reduced-motion`。
- 主题切换不能导致窗口跳尺寸、首帧闪白或卡片重排。
- 信息不可只靠颜色区分；文字、百分比和状态结构始终保留。

## 三、Cyber 实现规范

### 深色：Orbital Terminal

- 深海军蓝黑基底，青色为主光，紫红只作环境补光。
- 背景包含透视网格、低亮扫描线、两处受控光晕和边缘暗角。
- 卡片使用半透明技术玻璃、内描边、切角和局部品牌色扫描边。
- 标题用 Oxanium；数据和英文辅助信息用 Share Tech Mono。

### 浅色：Orbital Lab

- 冷白实验室基底，浅青蓝图网格，深青作为主操作色，紫色作次级标记。
- 卡片使用雾化玻璃与蓝灰技术描边，不使用普通白色商务卡片阴影。
- 保留同样的切角、字体、图标容器、套餐色和健康色语法。

### 赛博组件语言

- 主面板和卡片：小圆角加右上/左下切角，边缘存在局部高亮而非整圈霓虹。
- 图标按钮：六边形或切角方框容器，悬停时点亮，静止状态不过曝。
- 进度条：双层轨道、细刻度和窄光芯；颜色仍由 Token 健康状态决定。
- 套餐徽章：技术铭牌形态；六档配色完整且与 Token 健康色解耦。
- 动效：短促扫描、边框脉冲和数据刷新闪烁，持续时间不超过 600ms。

## 四、Claude 实现规范（Claude × Kami）

### 浅色：Warm Paper

- 采用 Kami 的暖纸基础：背景 `#F5F4ED`、抬升卡片 `#FAF9F5`、暖沙控件 `#E8E6DC`；不使用纯白和冷灰。
- 采用 Claude 式陶土橙 `#D97757` 作为主题高亮，并限制其面积；页面纹理仅保留近乎不可见的纸纤维。
- 深度主要由纸面明度差和极轻环形阴影表达，不使用泛黄滤镜、仿旧破损、硬投影和厚重压印。

### 深色：Warm Charcoal

- 采用 Kami 的暖炭黑：页面 `#141413`、卡片 `#30302E`，主文字回到暖纸白 `#F5F4ED`。
- 陶土橙提高少量明度以适配暗色，但不发光；卡片靠暖灰层级和柔和阴影分离。
- 套餐与 Token 健康色保持固定语义，但统一降低饱和度，避免破坏单一高亮的克制感。

### Claude 组件语言

- 英文标题、正文和数字统一使用 Literata；数字启用表格等宽特性以维持数据列对齐，中文分别回退宋体和系统字体。
- 图标按钮使用紧凑圆角暖灰控件；SVG 语义不变，线宽更细。
- 卡片使用简洁纸页和单侧品牌细线，不做不规则破损；进度条使用低饱和墨色填充。
- 会员套餐徽章使用带装订孔、纸面细纹与折角的微型书签；六档配色完整且与 Token 健康色解耦。
- 主面板、设置、供应商向导和认证表单均共享纸张、压印、墨线和圆润不规则边角。

## 五、验收清单

每套风格的浅色和深色必须共同检查：主面板、设置、添加供应商、OAuth/API 表单、
六档套餐徽章、五档 Token 进度条、余额行、错误状态、悬停、禁用、键盘焦点、
减少动态效果、macOS 透明窗口边缘和 Windows WebView2 不透明宿主。
