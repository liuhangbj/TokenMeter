# TokenMeter 独立审核清单

本清单用于开发前架构审核和开发后固定 diff 审核。审核 Agent 对仓库只读，
不负责修复。每项标记 `PASS`、`FAIL`、`BLOCKED` 或带原因的 `N/A`。

## A. 审核输入与边界

- [ ] 已取得原始需求，而不是只取得主开发 Agent 的实现摘要。
- [ ] 已取得任务质量契约、风险等级和明确非目标。
- [ ] 已记录当前分支、HEAD 和 `git status --short`。
- [ ] 已确认审核范围是工作树、暂存区还是固定 `base..head`。
- [ ] 已区分本轮问题、既有问题和其他用户未提交修改。
- [ ] 所有构建、日志、截图和测试配置都使用隔离临时目录。
- [ ] 审核前后仓库状态一致，未产生或覆盖文件。

## B. 需求与范围

- [ ] 每条用户需求都有代码路径和验证路径。
- [ ] 实现没有把任务缩减为单一成功路径。
- [ ] 明确处理空账户、加载中、失败、认证过期和字段缺失状态。
- [ ] 没有未经授权扩大到凭证重写、依赖安装、外部发布或架构替换。
- [ ] 任务非目标没有被错误实现或顺手删除。
- [ ] 相邻旧功能已经从 `module-checklists.md` 中选入回归范围。

## C. Diff 与代码卫生

- [ ] diff 只包含本轮需要的文件和生成产物。
- [ ] 没有密钥、API Key、Cookie、token、真实个人数据或无关本机绝对路径。
- [ ] 没有调试输出、临时开关、死代码、无解释 TODO 或测试绕过。
- [ ] 用户已有未提交修改没有被覆盖、格式化或夹带。
- [ ] 命名、错误类型、日志和模块职责符合现有代码风格。
- [ ] 新依赖说明必要性、许可、成本、失败降级和移除方式。

## D. 架构与三层边界

- [ ] `core/` 没有引入 tauri 依赖（scheduler 经 notify 回调的例外不变）。
- [ ] `platform/` 只放托盘、悬浮球窗口、系统浏览器、Dock 策略等平台差异。
- [ ] UI 层不直接 fetch 平台 API，不感知 provider 细节，只消费 commands。
- [ ] 单 WebView 原则没有被破坏（不新增运行时创建的第二个 WebView）。
- [ ] 新架构决策已更新对应 `docs`，没有让源码和文档继续冲突。

## E. Provider 契约与数据映射

- [ ] 前端仍只消费 `AccountCardModel`，没有按 `provider_id` 分支。
- [ ] 新字段映射遵守 `docs/05-provider-card-contract.md`：主值对应的额度档
  仍保留在 `items` 中（"主值 + 同一档进度条"同时存在）。
- [ ] `plan_tier()` 按大致月价映射 0–5 档，未知套餐使用中性色。
- [ ] 余额型（balance）只显示数值不显示进度条；额度型（quota）显示比例 +
  原始用量 + 重置时间。
- [ ] 余额健康状态只读主值，不受 Credit / Extra Usage 等余额项影响。
- [ ] 剩余额度类百分比是"总量 − 用量"计算，不是直接照搬用量百分比。
- [ ] 各平台返回精度不一致的数值（百分比小数、Token 大数）有统一展示规则。
- [ ] 新增供应商保存了脱敏真实响应样本，并有契约测试（主值、明细顺序、
  单位、套餐档位）。
- [ ] 无法满足主值契约的平台不创建空壳入口。

## F. 凭证、OAuth 与安全

仅 `R3` 或任务涉及认证、凭证、网络端点时强制全项执行。

- [ ] 凭证只在 `store.rs` 加密路径流转（AES-256-GCM + 0600 主密钥）。
- [ ] OAuth / 设备码流程的 token 刷新、过期和撤销路径完整。
- [ ] 本机 CLI 凭证导入只做读取，不修改源文件。
- [ ] 日志、错误消息、崩溃报告、截图和测试夹具不泄漏凭据。
- [ ] 新网络端点确认 TLS；Admin Key 等高权限凭证的使用范围最小化。
- [ ] 测试请求频率克制，不会对用户账号造成风控压力。

## G. 状态、调度与并发

- [ ] 刷新调度并发安全：多账户并发抓取不阻塞 UI，单账户失败不拖垮整体。
- [ ] 打开面板立即刷新与定时刷新不会互相覆盖成更旧的数据。
- [ ] 快速切换主题 / 账户 / 视图时，乱序结果不会覆盖当前状态。
- [ ] 悬浮球与面板的显隐、拖动、吸附状态机无死锁或竞态。
- [ ] App 重启后设置、卡片顺序、昵称、悬浮球布局正确恢复。
- [ ] 失败状态对用户可见（不得静默吞错显示成一切正常）。

## H. UI 实现与主题契约

此处审核代码是否遵循设计系统；视觉效果由验收 Agent 在真实 App 中最终确认。

- [ ] 卡片只使用 `ProviderCard` 标准行（quota / balance），没有新 UI 模板。
- [ ] 套餐色阶与 Token 健康色阶没有互相复用变量。
- [ ] 数字使用 `font-data`（表格数字），小字号中文可读。
- [ ] 变更在三套主题的 CSS 中都有对应处理，或确认走共享变量无需处理。
- [ ] 文案变长（长倒计时、长模型名、大数值）有收缩 / 省略约束，不挤压换行。
- [ ] 字体仍离线打包且许可证同步（THIRD-PARTY-LICENSES.txt）。
- [ ] 面板高度自适应（内容少时紧凑、多了才滚动）没有被破坏。

## I. 窗口、托盘与平台行为

- [ ] macOS：托盘定位、失焦关闭、Accessory 策略（隐藏 Dock）正常。
- [ ] Windows：工具窗口不抢焦点、不进任务栏、WebView2 兼容。
- [ ] 悬浮球：拖动、边缘吸附、收起/展开、多显示器定位、DPI 变化不错乱。
- [ ] 窗口创建 / 销毁不引入白屏、闪烁、残影。
- [ ] 系统浏览器打开链接使用平台正确路径（Windows ShellExecuteW）。

## J. 性能与稳定性

- [ ] 常驻内存没有显著增长（改动前后实测对比）。
- [ ] 面板打开无明显闪烁 / 跳动，滚动顺滑。
- [ ] 定时器、监听、任务在生命周期结束时释放。
- [ ] 刷新间隔变更立即生效，不需要重启。

## K. 测试、兼容与发布

- [ ] 测试覆盖需求而不是复制当前实现细节。
- [ ] 至少覆盖成功、失败、边界和一项回归。
- [ ] mock 没有掩盖真实 Contract、网络或生命周期问题。
- [ ] 版本号四处同步（package.json / package-lock.json / tauri.conf.json /
  Cargo.toml + Cargo.lock），先同步全部 lock 再打 tag。
- [ ] 已推送的 tag 没有被移动；漏内容升补丁号。
- [ ] release.yml 的 releaseBody 与实际变更一致。
- [ ] CI 三端产物与 `latest.json` 三平台元数据完整。

## L. 文档与对外一致性

- [ ] README、docs、营销物料中的功能描述与真实能力一致。
- [ ] 平台数量、主题数量、免费策略等数字承诺以 `addable_registry()` 等
  实际输出为准。
- [ ] 随仓库提交的设计源文件（HTML 排版等）自包含、引用素材随目录提交、
  可直接打开复现。
- [ ] 截图物料已脱敏（OCR / strings 扫描无 token、密钥、邮箱全文）。
